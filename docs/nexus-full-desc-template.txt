Template rules:
- Begin every new description with this exact visual rhythm: centered Grailwright logo; centered red title; centered italic one-line subtitle; `[line]`; compact opening copy; `[line]`; `Features`; feature list; `[line]`.
- Place a divider between the opening copy and `Features`.
- Begin the first opening paragraph with the full mod name in bold. Lead with the experience or problem solved, not installation, implementation details, or a generic “this mod” sentence.
- Keep the subtitle to one sentence and make it a player-facing pitch rather than a second title.
- Give each opening feature bullet a short bold label followed by a concrete explanation. Use three to six bullets and put the most distinctive features first.
- Use the optional second opening paragraph only for useful inspiration, design context, or differentiation; remove it instead of adding filler.
- Use the accent color [b]#C94A4A[/b] for the title and every major section header.
- Use exactly `Supports Windows and Linux.` for the platform line in Nexus descriptions; do not add a Proton qualifier.
- Use `[center][color=#C94A4A][size=6]...[/size][/color]` for the title.
- Use `[heading][color=#C94A4A][size=5]...[/size][/color][/heading]` for major headers.
- Use `[line]` between major sections.
- Avoid em dashes as comma substitutes. Prefer a comma unless the sentence genuinely requires stronger punctuation.
- Use `ks.tgfoa.<mod-slug>` for BepInEx plugin GUIDs and config file names.
- Link the first nearby mention of each published mod name with `[url=...]Mod Name[/url]`; leave close repeats unlinked or bold so the page does not become link-noisy.
- Use the optional Grail Floating Text diagnostics sentence only when the page has no more useful linked Grail Floating Text integration or dependency description. When used, put it in Compatibility or Optional Integrations: `[b]Optional diagnostics:[/b] [url=https://www.nexusmods.com/taintedgrailthefallofavalon/mods/247]Grail Floating Text[/url] can show critical load errors in-game, with details in the BepInEx log.`
- Include Updating only for config-owning mods and place it directly after Install.
- Keep the Config updates and Import Previous Settings paragraphs identical to the template. Tailor only the optional Automatically preserved line.
- List only settings the mod actually restores automatically. Omit Automatically preserved when the mod has no automatic durable-setting allowlist.
- Do not duplicate config-update, schema-reset, or previous-settings recovery explanations elsewhere on the page.
- Omit sections that do not apply, but keep the remaining section style identical.

[center][color=#C94A4A][size=6]Grail Floating Text[/size][/color]
[i]A shared floating text overlay for events and mod messages.[/i][/center]

[line]

[b]Grail Floating Text[/b] gives players and mod authors one shared overlay for short rewards, status updates, events, system notices, and debug messages.

It gives mod authors one standard place to send short reward, status, event, system, and debug messages instead of each mod drawing its own text stack. Messages can include shared tinted icon masks, appear near the configured screen position, pop in briefly, push older still-visible messages upward, and fade out cleanly.

For players, that means less overlapping HUD text. For mod authors, it means a small reflection-friendly API that can be used as an optional dependency without forcing a hard install requirement.

Grail Floating Text itself listens to explicit game events, hero consumable use, eligible hero health-stat increases, and the vanilla XP gain announcer. Immediate healing is eligible by default; periodic regeneration and timed healing effects require their separate setting. Healing and XP batching never change the visible entry or restart its timer: queued compatible gains receive a fresh full display cycle when their turn begins. Generic XP never merges with mod-claimed XP, and claimed XP requires the same source-specific key and presentation. Apart from its scoped potion replacement, GFT still avoids duplicating native advanced notification buffers such as items, proficiency, quests, objectives, recipes, fish, journal unlocks, location discovery, and hero level-up.

[heading][color=#C94A4A][size=5]Message Types[/size][/color][/heading]
Mods can send messages with a category, priority, style, icon ID, and optional collapse key.

[code]
| Category | Intended use                                      |
|----------|---------------------------------------------------|
| General  | Ordinary mod events                               |
| Combat   | Combat feedback                                   |
| Reward   | XP, loot, progress, or achievement-style feedback |
| Status   | Changing state such as Wyrd Scent                 |
| System   | Setup, compatibility, or availability messages    |
| Debug    | Diagnostic messages, hidden by default            |
[/code]

[code]
| Priority | Behavior                                                  |
|----------|-----------------------------------------------------------|
| Low      | Quiet messages, affected by source throttling             |
| Normal   | Default message priority                                  |
| High     | Bypasses source throttling and sorts ahead of normal text |
| Critical | Highest priority and critical styling fallback            |
[/code]

[b]Collapse keys[/b] are for status messages that should update in place. A mod can reuse one stable collapse key for a changing status so each state replaces the old visible line instead of building a stack of stale states.

[heading][color=#C94A4A][size=5]Built-In Styles[/size][/color][/heading]
Mods can request a named style, or pass a hex color such as [b]#FFD54A[/b].
Configured color-group names take priority over HTML named colors, so Purple, Pink, Red, Blue, Cyan, Orange, White, Gray, and other group names always use their matching Color settings. The dedicated Necrotic group defaults to dark green #25B792 for necromancy integrations without changing ordinary Green healing or poison text. Literal hex styles remain supported.

[heading][color=#C94A4A][size=5]Built-In Icons[/size][/color][/heading]
Mods can request a named icon ID. Blank or [b]Auto[/b] uses the default icon for the message style/category. [b]None[/b] or [b]Off[/b] suppresses the icon for that message.

Built-in icons cover general notices, rewards and currency, combat and weapon types, magic types, crime, crafting, consumables, exploration, healing, XP, four corpse-quality tiers, summons, and necromancy. Mod authors can find exact icon IDs and aliases in the bundled [b]docs/API.md[/b] reference.

Built-in icon PNG masks live in [b]GrailFloatingText/icons[/b]. Quick-wheel integrations can also register icons from their own package. GFT applies transparent-edge dilation, runtime mipmaps, trilinear filtering, and runtime style tinting to both.

[heading][color=#C94A4A][size=5]Configuration[/size][/color][/heading]
Configure Grail Floating Text through FoA Mod Manager or:

[code]
BepInEx/config/ks.tgfoa.grail-floating-text.cfg
[/code]

Settings cover overlay position and scale, timing and animation, icons, event notifications, consumable names and optional descriptions, Potion Poisoning activation, periodic-healing inclusion and consolidation, XP takeover, colors, and per-source controls. [b]ShowModDiagnosticMessages[/b] is one global switch for silencing in-game diagnostic messages from every integrated mod without disabling their detailed BepInEx logs or individual diagnostic settings. The installed config includes every current default and a description of each setting.

Most features are enabled by default. Full consumable descriptions, periodic healing, block, weak-spot, sneak-attack, Wyrd skill-toggle, and debug notices start disabled to avoid extra HUD noise.

[heading][color=#C94A4A][size=5]For Mod Authors[/size][/color][/heading]
Declare Grail Floating Text as a soft dependency so your mod still loads when GFT is absent:

[code]
[BepInDependency("ks.tgfoa.grail-floating-text", BepInDependency.DependencyFlags.SoftDependency)]
[/code]

Resolve the API by reflection through the loaded plugin assembly:

[code]
GrailFloatingText.NotificationApi
[/code]

The downloaded package includes [b]GrailFloatingText/docs/API.md[/b] with a copy-ready reflection resolver, exact overload signatures, safe invocation wrappers, capability names, examples, and the complete icon list. This page summarizes the stable common calls; the packaged reference is the canonical guide for the complete current surface.

NotificationApi is currently v13. Resolve exact overloads by their full signatures and use [b]SupportsFeature(feature)[/b] when selecting optional behavior. If GFT, an overload, or a capability is unavailable, skip that route and keep your mod functional without throwing or changing another mod.

QuickWheelPanelApi v15 provides a separate persistent panel surface:

[code]
GrailFloatingText.QuickWheelPanelApi
TrySet(sourceId, leftTitle, leftSubtitle, leftTexts, leftIconIds, leftStyles, leftResourceTexts, leftResourceIconIds, leftResourceStyles, leftSummaryRowCount, rightTitle, rightSubtitle, rightTexts, rightIconIds, rightStyles, opacity, tooltipOpacity, fadeSeconds, rightOffset, topOffset, scale, panelColumnWidth, columnGap, panelBackgroundOpacity, panelBackgroundPadding, textShadowEnabled, textShadowOpacity, textShadowOffset, textShadowSoftness, textShadowStrength, textOutlineEnabled, textOutlineColor, textOutlineOpacity, textOutlineWidth, textOutlineStrength, whiteTextOutlineStrengthMultiplier, headerColor, subheaderColor)
SetTooltipActive(sourceId, active)
Clear(sourceId)
[/code]

QuickWheelPanelApi v15 adds caller-controlled 0 through 200 reference-pixel spacing between its columns while retaining the caller-declared left summary boundary, slight fixed gap before ordinary statistics, 160 through 400 reference-pixel column width, and two charcoal column backplates. Opacity accepts 0 through 1, with zero disabling them, and padding accepts 0 through 32 reference pixels. Each backplate remains one simple UI quad sized to its column's content and rendered behind the text and icons. Each receives its own small 128x256 procedurally generated black alpha mask, so their multi-scale mottling, fine fibers, irregular silhouette, and surface variation differ while very dark scenes remain black. Guaranteed transparent outer gutters, broad feathering, additional texture bleed, and subtly rounded corner intersections remove hard rectangular cutoffs and sharp points for a higher-quality tooltip-like finish without loading a copied game texture. The API also supports 0 through 1 underlay softness and a caller-controlled 0.5x through 2.0x outline-strength multiplier for semantic White text. Icons, Pale text, and other styles retain the caller's configured strength. Outline width and shadow offset accept 0 through 16, while both strength values accept 1 through 8. Supported TextMesh Pro SDF fonts render their outline and underlay from one cached material-backed glyph mesh. Unsupported materials use a bounded six-copy compatibility fallback instead of layered geometry. The caller owns panel lifetime, row limits, resource values, the summary boundary, column width and spacing, backplates, text-effect settings, shared header/subheader colors, and the White-text multiplier. GFT owns rendering, font resolution, row style colors, icon texture quality, position, and the configured fade between normal and tooltip-active opacity.

[b]Broadcasting a compatibility notice:[/b] verify the exact loaded plugin, DLL, or enabled setting in your own mod, then call the dedicated NotificationApi v13 compatibility surface. GFT supplies the shared [b]Warning[/b] style, [b]System[/b] category and duration, [b]High[/b] priority, [b]warning[/b] icon, stable collapse behavior, [b]OnMainMenu[/b] delivery, and diagnostic logging. Use your plugin GUID as [b]sourceId[/b], a stable source-scoped [b]conflictId[/b], concise player-facing text, and the exact detected evidence as [b]diagnosticDetails[/b]. GFT respects the player's compatibility-notice and source controls and never changes the other mod.

[code]TryShowCompatibilityNotice(PluginGuid, "incompatible-other-mod", conciseText, diagnosticDetails)[/code]

Probe [b]CompatibilityNotices[/b] and resolve this four-string API v13 method by its exact signature. If it is unavailable or returns [b]false[/b], keep your normal log warning and do not treat GFT as a required dependency.

A plugin rejected by BepInEx cannot call any runtime API. GFT therefore also reads BepInEx's verified hard-incompatibility dependency errors, identifies the rejected and conflicting plugins, and presents the same main-menu warning automatically. This covers conflicts such as Soul and Service being installed with Avalon Summons or Better Summon without hard-coding those pairs into GFT.

Fade-in stays at [b]DefaultFadeSeconds[/b]. Fade-out scales with total message duration, from 60% to 200% of that baseline and never longer than half the message lifetime. With the defaults, Medium fades out over 0.25 seconds and System over 0.5 seconds.

API v7 deferred event call shape:

[code]
TryShowEvent(sourceId, eventId, text, style, category, priority, collapseKey, iconId, durationBucket, deliveryPoint, fadeSeconds, opacity)
[/code]

Delivery points are [b]Immediate[/b], [b]OnMainMenu[/b], and [b]OnLoad[/b]. OnMainMenu waits for the initialized interactive title view. OnLoad waits for an initialized hero and world, completed location/HLOD loading, a dismissed loading screen, a completed camera transition, no covering fullscreen video or cutscene, and a focused game window. Deferred messages persist until shown, and their duration begins on their first eligible rendered frame.

API v8 consolidated XP claim call shape:

[code]
TryClaimConsolidatedXpGain(sourceId, eventId, consolidationKey, textFormat, style, category, priority, iconId, durationBucket, expectedAmount, fadeSeconds, opacity)
[/code]

Call it immediately before changing hero XP. GFT combines only matching keys from the same source and presentation; use [b]{xp}[/b] or [b]{amount}[/b] in the format and a different key for every meaning that must remain separate. Fall back to the v6 claim when v8 is unavailable.

NotificationApi v10 adds XP claim cancellation:

[code]
TryCancelXpGainClaim(sourceId, eventId, expectedAmount)
[/code]

If the XP mutation fails after reserving a v6 or v8 claim, call this immediately with the same source, event, and expected amount. GFT removes the newest matching unconsumed claim so it cannot later describe a reward that was not granted.

NotificationApi v12 can restyle one exact synchronous built-in event without bypassing that event's enablement, text, duration, minimum, or consolidation settings:

[code]
TrySetBuiltInEventPresentationClaim(sourceId, eventId, presentationEventId, style, iconId, active)
[/code]

NotificationApi v11 can claim ownership of one built-in event when an integration supplies or intentionally suppresses its replacement:

[code]
TrySetBuiltInEventClaim(sourceId, eventId, active)
[/code]

Set either claim immediately around the exact synchronous event and always release it from a [b]finally[/b] block or Harmony finalizer. Presentation claims are source-scoped; suppression claims take priority, and neither changes user configuration.

API v6 one-shot XP claim call shape:

[code]
TryClaimXpGain(sourceId, eventId, text, style, category, priority, iconId, durationBucket, expectedAmount, fadeSeconds, opacity)
[/code]

The next matching XP stat gain uses the claimed text/event/style/icon instead of the generic XP event. API v6 claims remain separate.

API v4 event-aware call shape:

[code]
TryShowEvent(sourceId, eventId, text, style, category, priority, collapseKey, iconId, durationBucket, fadeSeconds, opacity)
[/code]

Duration buckets are [b]VeryShort[/b], [b]Short[/b], [b]Medium[/b], [b]Long[/b], [b]VeryLong[/b], and [b]System[/b]. Their defaults are 3, 3.5, 4, 4.5, 5, and 10 seconds respectively. System is intended for startup, compatibility, config-reset, and load-time error messages. Empty or unknown bucket names use [b]Medium[/b].

API v3 call shape:

[code]
TryShow(sourceId, text, style, category, priority, collapseKey, iconId, durationSeconds, fadeSeconds, opacity)
[/code]

API v2 calls still work:

[code]
TryShow(sourceId, text, style, category, priority, collapseKey, durationSeconds, fadeSeconds, opacity)
[/code]

[heading][color=#C94A4A][size=5]Compatibility[/size][/color][/heading]
Grail Floating Text draws its own overlay when another mod queues a message, when an enabled built-in default game event fires, when the hero's health reports an eligible positive change, or when the vanilla XP announcer reports an XP gain. It does not modify combat, quests, saves, items, enemies, or stat values. Built-in event notices are event-driven and throttled or consolidated where needed; they do not poll combat, inventory, quest, or save state.

[b]Optional integrations:[/b] The Current Integrations section above is the authoritative list of richer repo integrations. Other Grailwright mods also use the shared optional startup path for deferred config-reset and critical load-error notices without requiring GFT to be installed. Any mod author can use the compatibility-notice API, while BepInEx hard-incompatibility rejections are surfaced directly by GFT because the rejected mod never reaches startup.

If messages are too frequent, use the category toggles or the per-source sections in the config. If messages are missing, make sure [b]Enabled[/b] is true, the relevant category is enabled, and the sending mod is installed and configured to use Grail Floating Text.

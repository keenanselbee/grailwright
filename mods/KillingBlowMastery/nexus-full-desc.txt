[center][color=#C94A4A][size=6]Killing Blow Mastery[/size][/color]
[i]Finisher sounds and modest proficiency XP for the skill that lands the kill.[/i][/center]

[line]

[b]Killing Blow Mastery - Finisher Sounds and Proficiency XP[/b] gives a small extra combat proficiency reward to the skill that actually lands an enemy's killing blow.

The goal is to make side weapons, shields, archery, and magic less painful to train without turning last-hitting into a replacement for normal combat practice. Soften an enemy with your main setup, swap to the weapon or spell you want to train, and earn a modest finishing bonus if that source lands the kill.

It also adds optional finisher feedback: a shared [url=https://www.nexusmods.com/taintedgrailthefallofavalon/mods/247]Grail Floating Text[/url] reward message and category-based killing blow sounds for blades, axes, blunt weapons, bows, shields, unarmed attacks, and several magic types.

[heading][color=#C94A4A][size=5]Combat Finishers and GloryKills[/size][/color][/heading]
[b]AutomaticCombatFinishersEnabled[/b] controls the killing-blow animations the game starts automatically during ordinary melee attacks. It is enabled by default.

[b]CombatExecutionMode[/b] controls the separate interaction available while aiming at a living enemy:
[list]
[*][b]Vanilla:[/b] Preserve the game's normal combat execution rules.[/*]
[*][b]GloryKill:[/b] Show [b]Execute[/b] for an eligible hostile combatant at or below the configured health threshold while the hero is close enough and has a melee weapon.[/*]
[*][b]Off:[/b] Remove only the living-enemy combat execution interaction.[/*]
[/list]

The GloryKill threshold defaults to 15% of maximum health. The game's normal distance, kill-prevention, and external-death safeguards remain active. After those checks pass, KBM first selects from the equipped melee weapon's loaded execution animations, then falls back to its loaded normal finisher animations when the execution list has no playable hero animation. The game's situational direction, stagger, and random-chance filters do not block the prompt. Loaded animation assets and the native target-template restriction still apply. GloryKills use the existing finisher animation system and still count as killing blows for this mod's normal rewards.

[b]ExpandedGloryKillTargets[/b] is experimental and disabled by default. The shipped combat execution animations are authored for humanoid targets. Enabling this option lets additional hostile enemy templates attempt them, but unsupported body types can animate or align incorrectly.

These settings do not alter the separate hold-interact story execution used for important unconscious NPCs. Disable automatic combat finishers and set combat execution mode to Off to remove combat finisher animations while leaving those story executions intact.

When [b]Diagnostics[/b] is enabled, throttled per-target log entries identify health and safety rejections, missing execution lists, native animation-selection failures, the native activation delay, and successful Execute-prompt availability.

[heading][color=#C94A4A][size=5]Finisher Sounds[/size][/color][/heading]
The default sound mode is [b]WeaponSpecific[/b]. The mod tries to play a matching category sound for the kill source, then uses FMOD for playback with optional no-repeat selection, subtle pitch randomization, and distance-based volume fade.

[code]
| Mode           | Sound style       |
|----------------|-------------------|
| WeaponSpecific | category pools    |
| Soulslike      | killing_blow1.wav |
| GoatTest       | goat.wav          |
| Off            | silent            |
[/code]

[b]FinisherSoundRangeVolume[/b] applies to all active sound modes, including [b]WeaponSpecific[/b], [b]Soulslike[/b], and [b]GoatTest[/b]. Set it to 0 to disable distance fade. The default 1 uses the full 0m = 100%, 30m+ = 10% curve:

[code]
| Distance | Volume |
|----------|--------|
| 0m       | 100%   |
| 7.5m     | 78%    |
| 15m      | 55%    |
| 22.5m    | 33%    |
| 30m+     | 10%    |
[/code]

If FMOD playback fails, the mod falls back to the older Unity AudioSource path and logs the failure when Diagnostics is enabled.

[b]UseNonCorporealEnemySounds[/b] is enabled by default. Matched non-corporeal targets use [b]non_corporeal1.wav[/b] through [b]non_corporeal5.wav[/b] only, overriding weapon, magic, Soulslike, and [b]_dry[/b] routing for those targets. [b]GoatTest[/b] still uses [b]goat.wav[/b] for diagnostics, and [b]Off[/b] remains silent.

[b]UseBloodlessSoundVariants[/b] is enabled by default. Targets whose names, templates, or type text match [b]BloodlessSoundBlacklistTerms[/b] try matching [b]_dry[/b] files before their normal pool sound. [b]BloodlessSoundWhitelistTerms[/b] can force normal sounds for specific targets. This only changes sound routing; it does not change XP or kill eligibility.

[heading][color=#C94A4A][size=5]Sound Routing[/size][/color][/heading]
Classified kills use their specific pool by default. That keeps, for example, a two-handed axe kill from falling through to the general killing_blow pool unless you explicitly enable that fallback.

[code]
| Group      | Kill type             | Sound pool        |
|------------|-----------------------|-------------------|
| Target     | matched non-corporeal | non_corporeal     |
| One-Handed | blunt                 | one_handed_blunt  |
| One-Handed | axe                   | one_handed_axe    |
| One-Handed | blade/dagger/sickle   | one_handed_blade  |
| One-Handed | unknown subtype       | one_handed_blade  |
| Two-Handed | blunt                 | two_handed_blunt  |
| Two-Handed | axe                   | two_handed_axe    |
| Two-Handed | blade/polearm         | two_handed_blade  |
| Two-Handed | unknown subtype       | two_handed_blade  |
| Archery    | short bow             | archery_short     |
| Archery    | medium/unknown bow    | archery_medium    |
| Archery    | heavy bow             | archery_heavy     |
| Shield     | bash                  | shield_bash       |
| Unarmed    | unarmed               | unarmed           |
| Magic      | blood                 | magic_blood       |
| Magic      | fire                  | magic_fire        |
| Magic      | frost                 | magic_frost       |
| Magic      | poison                | magic_poison      |
| Magic      | electric              | magic_electric    |
| Magic      | wyrdness              | magic_wyrdness    |
| Magic      | water                 | magic_water       |
| Magic      | other                 | magic_arcane      |
| Other      | unclassified eligible | killing_blow      |
[/code]

Broad [b]one_handed[/b], [b]two_handed[/b], [b]archery[/b], [b]shield[/b], and [b]magic[/b] fallback pools are not used in this release.

For bloodless targets, each routed pool can have matching [b]_dry[/b] files. The dry file is tried before the normal file it replaces:

[code]
| Normal file           | Bloodless variant        |
|-----------------------|--------------------------|
| two_handed_blade1.wav | two_handed_blade1_dry.wav |
| magic_fire3.wav       | magic_fire3_dry.wav       |
| killing_blow1.wav     | killing_blow1_dry.wav     |
[/code]

[heading][color=#C94A4A][size=5]Notifications[/size][/color][/heading]
Notifications are on by default and show the exact bonus and skill.

[code]
Default text: Killing blow: +{xp} {skill}
Example:      Killing blow: +8 Two-Handed
[/code]

[b]NotificationMode[/b] defaults to [b]GrailFloatingText[/b], the optional shared [url=https://www.nexusmods.com/taintedgrailthefallofavalon/mods/247]Grail Floating Text[/url] overlay. With Grail Floating Text 2.3.1 or newer, recognized one-handed and two-handed kills use specific sword, axe, blunt, dagger, or spear icons while the awarded proficiency remains One-Handed or Two-Handed. Sickles use the One-Handed Axe icon while retaining blade-pool audio. Older GFT versions and unknown subtypes use the broad proficiency icon. Archery, Shield, Unarmed, and Magic continue to use their skill-level icons. With Grail Floating Text 1.4.7 or newer, killing-blow rewards use the [b]killing-blow[/b] event ID and are red by default through Grail Floating Text's editable [b]RedEvents[/b] group.

[b]NotificationTextFormat[/b] supports:

[code]
{xp}
{skill}
{enemy}
{weapon}
{enemyXP}
[/code]
